## Diagnostic continuation and resource boundary

The evaluation first emits `s45.evaluation-pending/1` with `state: diagnostics-pending`, the complete raw secondary report and hashes. This is an intermediate operator artifact, not measured results for publication. The attempt stays labels-released. Roy must have appointed the independent gate operator before execution; this builder and its children never classify the data. Continue with the identical eval arguments plus `--resume --diagnostics ../diagnostics.json --write-output`. Prediction, freeze and manifest hashes must remain identical. Only then does the CLI emit `s45.results/1` and persist `results/results.json` plus `results/results.md`; inspect those artifacts rather than redirecting npm's banner-bearing stdout or copying numbers manually. The supplementary field preserves macro recall, signature/anchor strata, selected atoms, defect density, clean shares, traps and diagnostic provenance. Random partial-hunk counts sum across permutations; recall and selected atoms average permutations. Publication remains a separate permission.

After canonical report publication or an output failure, recover without rereading labels or reevaluating:

```sh
npm run eval -- --gate ../gate1.json --split heldout --attempt-id S45-001 --custody-dir ../sealed/custody --recover-report --write-output
```

Do not supply --resume, --release-dir or --diagnostics in recovery mode. Recovery verifies the same gate, freeze, attempt, prediction and final-report hashes, then reads the immutable custody heldout.report.json (or its verified pending artifact) and exports it. Completion follows durable canonical report publication. Identical existing result files are accepted; conflicting files are preserved and cause an error. Drop --write-output for stdout-only recovery when output paths conflict; use a direct quiet runner if collecting stdout, since npm may print banners. Never delete/reset the attempt or change a conflict into a new scientific run. Pending diagnostic continuation and final report recovery are distinct operations.

`npm run eval` uses scripts/run-eval.ts to impose a 15-minute subprocess timeout and a V8 heap ceiling. This is not proof of a total-RSS limit: the Normal-mode operator must supply an OS/job memory boundary of 2 GiB and verify it in deferred validation. An exhausted or killed attempt is not a successful result. Child errors and timeout exit nonzero.
